# EnvSwitch 使用说明书

面向使用者的操作手册：怎么装、怎么用、每个设置项是什么意思、出问题查什么。
设计与实现依据见 [架构方案](架构方案.md)，界面视觉规范见 [设计语言](设计语言.md)。

- 适用平台：Windows 10 / 11 x64（不区分 32/64 位系统盘，只要求 x64 CPU）
- 权限要求：**全程不需要管理员权限**，也不需要开启开发者模式
- 适用版本：v1.0.0 起（`envs version` 可查当前版本）

---

## 1. 五分钟上手

```powershell
envs install node 22.22.0     # 下载 → 校验 → 解包 → 跑一遍 --version
envs use node 22              # 切换激活版本（毫秒级，只重指一个链接）
envs status                   # 看各工具当前激活版本与 PATH 里实际胜出的是谁
envs gui                      # 打开桌面应用（同目录有 EnvSwitch.exe 时）
```

第一次执行 `use` 或 `install` 时（安装版则在装完时自动做一次），EnvSwitch 会往**你的用户 PATH** 写入 5 条路径并广播刷新，**之后再也不动注册表**。已经打开的终端不会变，**新开一个终端**就是新版本 —— 这是 Windows 给每个进程固定环境块的机制，不是 bug。

只想用图形界面：双击 `EnvSwitch.exe`，在总览页点工具卡片 → 详情页「加载可用版本」→ 安装 → 切换。

**PATH 生效范围，先看清楚**：EnvSwitch 只会自动把 **node、python、go** 三个运行时和 **npm / npx / pnpm / pnpx / yarn** 五个命令入口接进你的 PATH。其余工具（Rust、PHP、Deno、Bun、uv、JDK、Maven、Gradle、.NET、kubectl、Terraform）会被下载、进版本库、可切换，但**不会自动出现在 PATH 里** —— 想直接敲命令，需要自己加一条路径，方法见 §4。

## 2. 安装与卸载 EnvSwitch 本体

### 2.1 安装版（推荐）

从 [Releases](https://github.com/HUIdada1/EnvSwitch/releases) 下载 `EnvSwitch-Setup-vX.Y.Z.exe`。

- per-user 安装（全程不提权），默认目录 `%LOCALAPPDATA%\Programs\EnvSwitch`，不写 `Program Files`、不动系统 PATH
- 装入 `EnvSwitch.exe`（桌面端）、`envs.exe`（命令行）与 logo，建开始菜单快捷方式和控制面板卸载项
- 安装过程会自动跑一次 `envs path ensure`，把 §4 的 5 条路径写进你的**用户 PATH**；免安装版则是在首次 `use` / `install` 时写入
- 会检测 WebView2 Runtime：缺失时只弹提示、不阻塞安装，此时 GUI 打不开但 CLI 照常可用（补装 Microsoft Edge WebView2 Runtime 即可）
- 完成页勾选「启动 EnvSwitch 并开启开机自启」→ 写 `HKCU\...\Run` 并以 `--tray` 静默起托盘

### 2.2 免安装版

下载 `EnvSwitch-win-x64.zip`（附 `SHA256SUMS.txt`），解压到任意目录即可运行。
解压目录会在首次启用时作为第 5 条 PATH 条目写入你的用户 PATH，所以**解压后就别再挪动**；确实要挪，先 `envs path restore`，挪完再 `envs path ensure`。

### 2.3 从源码构建

```powershell
.\build.ps1            # CLI + GUI 一起构建，产物在 build\bin\
.\build.ps1 -Cli       # 只要 envs.exe
.\build.ps1 -Gui       # 只要 EnvSwitch.exe（会先 npm run build 前端）
```

依赖 Go 1.22+、Node 16+。GUI 用 `go build -tags production` 直接构建（前端 `frontend/dist` 已 embed 进 exe），不需要装 wails 命令行；要用 `wails dev` 热调试前端才需要 `go install github.com/wailsapp/wails/v2/cmd/wails@latest`。

### 2.4 卸载

1. 控制面板（或开始菜单里的「卸载 EnvSwitch」）走卸载器：它会先结束 `EnvSwitch.exe`，再自动执行 `envs path restore` 清掉它写入的 PATH 条目（清理前的用户 PATH 原值快照在 `%LOCALAPPDATA%\EnvSwitch\path-backup.json`），然后删除程序文件、快捷方式、`HKCU\...\Run` 自启值与卸载注册项
2. 免安装版没有卸载器：先手动 `envs path restore`，再删解压目录
3. 版本库不会被自动删除：`%LOCALAPPDATA%\EnvSwitch\store` 里是各工具的完整版本文件，确认不要了再手动删（这部分通常占几个 GB）

按 §4.1 自己加过 `current\<工具>` 的，那条也会被第 1/2 步一并移除（同属 `current\` 前缀）；卸载后如仍需那些工具，请自行恢复到原来的安装路径。

### 3.2 总览页

### 3.3 工具详情页

- 进页面只读本地，**不联网**；要看可装版本点「加载可用版本」

- 安装时行内显示进度、速率、剩余，可点「取消」中断，下次安装同一包会**断点续传**
- 标为「收编自 nvm」的行没有删除按钮：文件归 nvm-windows 所有，EnvSwitch 只借用不改动

### 3.4 设置页

| 设置项 | 作用 | 说明 |
|--------|------|------|
| 开机自启 | 写 / 删 `HKCU\...\Run` 的 `EnvSwitch` 值 | 静默起托盘，不弹窗口 |

| 启动时检查更新 | 存盘 | 当前版本该开关尚未接线，见 §13 |
| node / npm / pnpm / yarn 下载源 | `npmmirror` ↔ `official` | 也可写 `custom` 并配自定义地址，见 §9 |
| GitHub 下载代理加速前缀 | 给 GitHub 直链加前缀 | 如 `https://ghproxy.net/`，影响 uv、php、deno、bun、terraform 等走 GitHub 的源，以及自更新清单 |
| 远程版本索引缓存时长 | 默认 10 分钟 | 1–1440；设 0 无效，最少 1 |
| 版本库实际存储目录 | 只读展示 + 一键打开 | 改址要用命令行，见 §8 |

### 3.5 系统托盘

- **左键单击**：显示 / 隐藏主窗口
- **右键**：动态菜单，每个工具一项（标题后跟当前版本），展开列该工具已装版本（最多 40 条，当前项打勾，外部来源带 `(nvm)` 标记），末尾「管理 <工具>…」跳详情页；底部固定「打开主界面 / 开机自启 / 检查更新 / 退出 EnvSwitch」
- 点「退出 EnvSwitch」会把「缩到托盘」关掉再退出，否则下次点 × 仍会缩回托盘
- 只允许单实例：重复启动的进程会静默退出，已有实例的窗口不会被唤醒

## 4. 切换为什么是毫秒级

```
%LOCALAPPDATA%\EnvSwitch\
├─ store\<工具>\<版本>\     版本真实文件（一个版本一份，互不覆盖）
├─ current\<工具>           激活链接（junction）→ 指进 store 里某个版本
└─ bin\shims\<命令>.cmd     npm / npx / pnpm / pnpx / yarn 的稳定入口
```

PATH 里放的是**永远不变**的 `current\node`、`current\python`、`current\go`、`bin\shims` 以及 `envs.exe` 所在目录，共 5 条，全部写在**用户 PATH**（`HKCU\Environment`）。切换版本只是把这个 junction 重指向另一个 store 目录，因此：

- 不改注册表、不需要管理员、不需要开发者模式（junction 是普通目录重解析点，非符号链接）
- 可以同时留多份版本，来回切没有下载成本
- 卸载干净：删目录即可，PATH 里不会留下失效残项

### 4.1 让其余工具也能直接敲命令

node / python / go 之外的工具，激活链接同样建在 `current\<工具>`，只是没被写进 PATH。手动补一次即可，**以后切换版本不用再动注册表**（因为链接路径不变）：

```powershell
# PowerShell：给 JDK 接上 PATH（管理员无关，只写你自己的用户 PATH）
[Environment]::SetEnvironmentVariable(
  'Path',
  [Environment]::GetEnvironmentVariable('Path','User') + ';' + "$env:LOCALAPPDATA\EnvSwitch\current\java",
  'User')
```

或者图形化：Win+R → `sysdm.cpl` → 高级 → 环境变量 → 用户变量 `Path` → 新建 → 填 `%LOCALAPPDATA%\EnvSwitch\current\<工具>`。

各工具的可执行文件就在 `current\<工具>` 这一层（Maven / Gradle / Go / Rust / JDK 的 `bin` 已经由激活链接包含在内），直接指它就行。反过来说：因为 `envs path restore` 是按 `current\` 前缀判归属清理的，**你手动加的这条也会被一并移除**，重装 EnvSwitch 后要重新添加。

## 5. 命令行参考

命令名 `envs`。工具与版本可以写成 `pnpm@9.12.3`，也可以 `pnpm 9.12.3`；版本省略即 `latest`，也支持前缀（`envs use node 22` 取匹配到的最高版本）。

| 命令 | 说明 |
|------|------|
| `envs status` | 各工具激活版本、来源、激活链接目标、PATH 实际胜出路径 |
| `envs list <tool>` | 本机已装版本，当前项标 `◀ 当前` |
| `envs list <tool> --remote [--filter 22]` | 远程可装版本（带 LTS/日期/大小/已装标记）；离线时退回索引缓存并提示 |
| `envs install <tool> <ver>` | 下载 → 校验 → 解包 → 冒烟自检；当前无激活版本时装完自动切上 |
| `envs use <tool> <ver>` | 切换激活版本。首次启用会写用户 PATH。`--no-path` 只切链接不碰注册表 |
| `envs remove <tool> <ver>` | 卸载版本库里的某个版本，交互确认。`-y` 跳过确认；删当前激活版本需 `--cascade`，删完自动切到剩余最新 |
| `envs which <tool>` | 当前真正生效的可执行文件全路径；不是 EnvSwitch 提供的会提示 |
| `envs doctor` | 体检（见 §12）；`--bundle` 另存诊断包到 `logs\diag-<时间戳>.json` |
| `envs config show` | 打印全部配置（JSON） |
| `envs config set <key> <value>` | 键：`mirror.node` / `mirror.python` / `mirror.go` / `mirror.<任意工具>` / `proxy` / `store` |
| `envs path ensure` | 写入并校验 EnvSwitch 的 PATH 条目 |
| `envs path restore` | 移除全部 EnvSwitch 的 PATH 条目（旧值先备份） |
| `envs clean` | 清空下载缓存与索引缓存，不动已装版本 |
| `envs autostart on\|off\|status` | 开机自启（HKCU Run，免管理员）；`on` 需要同目录有 `EnvSwitch.exe` |
| `envs gui` | 打开桌面应用 |
| `envs self update` | 检查并热更新自身（GUI 会带 `--updated` 自动重启） |
| `envs self rollback` | 回滚到上一版本（`.old` 还在时有效） |
| `envs version` | 输出版本与构建所用 Go |
| `envs help [命令]` | 任意命令的帮助 |

**`--json` 支持范围**：`status`、`list`（本机分支）、`doctor`、`config show`、`version`。其余命令只输出人类可读文本。

**退出码**：`0` 成功 / `1` 失败或未找到 / `2` 参数用法错 / `3` 网络 / `4` 校验失败 / `5` 权限不足。

## 6. 配置文件

`%LOCALAPPDATA%\EnvSwitch\settings.json`，界面和命令行改的是同一份，保存为原子写（先 `.tmp` 再改名）。

| 键 | 默认 | 含义 | GUI 入口 | CLI 入口 |
|----|------|------|----------|----------|
| `autostart` | `false` | 开机自启意图 | 开关 | `autostart on/off` |
| `closeToTray` | `true` | 点 × 缩托盘 | 开关 | — |
| `checkUpdateOnStart` | `true` | 启动检查更新 | 开关 | 未接线 |
| `storePath` | 空 | 版本库目录覆盖 | 只读 | `config set store` |
| `mirrors` | 见 §9 | 各工具下载源 | 4 个下拉 | `config set mirror.*` |
| `proxy` | 空 | GitHub 代理前缀 | 输入框 | `config set proxy` |
| `indexCacheMinutes` | `10` | 远程索引缓存分钟 | 数字框 | 改文件 |
| `enabledTools` | 6 个默认工具 | 保留字段，当前不参与过滤 | — | 改文件 |

配置缺失或损坏时会自动回退到默认值，不会导致程序起不来；`store`、`current` 等目录按需创建。

## 7. 支持的工具与源

| 工具 | id | 安装源 | 哈希来源 | 备注 |
|------|----|--------|----------|------|
| node.js | `node` | npmmirror（可切官方/自定义） | 官方 `SHASUMS256.txt` | 可收编 nvm-windows 已装版本 |
| python | `python` | python-build-standalone | 官方 release 附带 | `auto`：GitHub 快探失败自动退 NJU 镜像 |
| Go | `go` | golang.google.cn（可切官方 / 阿里云） | 官方 `sha256` 清单 | 解压后 `bin` 子目录进 PATH |
| Rust | `rust` | static.rust-lang.org | 官方 `.sha256` | 镜像选项尚未生效 |
| PHP | `php` | windows.php.net | 官方 `.sha256.txt` | 版本列表内置 4 条，不拉远程索引 |
| Deno / Bun | `deno` `bun` | GitHub Releases | API 直供 digest | — |
| npm / pnpm / yarn | `npm` `pnpm` `yarn` | registry（npmmirror / npmjs / 自定义） | `dist.integrity` | 命令入口经 `bin\shims` |
| uv | `uv` | GitHub Releases | 伴生哈希（缺则跳过强校验并提示） | Python 侧包管理器 |
| JDK (Temurin) | `java` | Adoptium API | 官方 `.sha256.txt` | 只管理版本，**不写 `JAVA_HOME`，也不自动进 PATH**（见 §4.1） |
| Maven | `maven` | Apache dist（可切阿里云镜像） | 官方 `.sha256` | 用文件探测代替冒烟执行 |
| Gradle | `gradle` | services.gradle.org | 官方 `.sha256` | 列表取最近 40 条 |
| .NET SDK | `dotnet` | dotnet.microsoft.com | 官方清单 | 每个通道只给最新 SDK |
| kubectl | `kubectl` | dl.k8s.io | 伴生 `.sha256` | 单文件 exe，不解包 |
| Terraform | `terraform` | releases.hashicorp.com | `_SHA256SUMS` | 列表取最近 80 条 |

安装流水线固定四步：**下载**（`.part` + `Range` 断点续传，服务器不支持续传则从头下）→ **哈希校验**（内置哈希 → registry integrity → 伴生 `.sha256` / `.sha256.txt` → `_SHA256SUMS`；全都没有则跳过强校验并明确提示）→ **解包落位**（先落临时目录再改名，避免半成品）→ **冒烟自检**（跑 `<exe> --version`；npm/pnpm/yarn 用当前激活的 node 直接跑包内入口脚本；Maven/Gradle 改为探测关键文件）。任何一步失败都不留脏目录，也不影响当前激活版本。

## 8. 数据放在哪、怎么搬家

```
%LOCALAPPDATA%\EnvSwitch\
├─ settings.json          用户配置
├─ store\<工具>\<版本>\    版本库（占空间主力）
├─ current\<工具>         激活 junction
├─ bin\shims\*.cmd        JS 工具命令入口
├─ downloads\             安装包缓存（*.part 是未完成下载）
├─ downloads\cache\*.json 远程版本索引缓存
├─ logs\diag-*.json       诊断包（跑过 envs doctor --bundle 才有）
├─ update\                自更新暂存包与心跳文件
└─ path-backup.json       写 PATH 前的用户 PATH 旧值快照
```

**换到别的盘**：

```powershell
envs config set store D:\Dev\envswitch-store
```

注意：改址只影响**之后**的安装。已有的 `current\` 链接仍指向旧目录，这些版本会被识别为外部来源（只读、可切换但不能再被 EnvSwitch 删除）。正确搬家顺序：

1. `envs path restore`
2. 关闭 EnvSwitch（含托盘）
3. 把旧 `store` 目录整体移到新位置
4. `envs config set store <新路径>`
5. 对每个用过的工具重新 `envs use <tool> <ver>`（重建 junction）
6. `envs path ensure`

**临时隔离测试**（不动真实环境）：设环境变量 `ENVS_HOME=<独立目录>`，所有读写都落到那里。另有 `ENVS_NO_PATH=1` 只建目录不碰注册表。

## 9. 国内网络：镜像与代理

- **node / npm / pnpm / yarn**：默认 npmmirror，设置页可直接切 `official`（registry.npmjs.org / nodejs.org）。想指到公司私服：`envs config set mirror.node custom`，再在 `settings.json` 的 `mirrors` 里加一条 `"node.url": "https://your.mirror/-/binary/node"`（npm 系同理用 `npm.url`）。
- **python**：`auto`（默认，先试 GitHub API，慢或失败自动退回 NJU 镜像）、`github`、`nju`。
- **go**：`google.cn`（默认）、`official`、`aliyun`。
- **maven**：`aliyun` 生效，其余走 Apache 官方。
- 以上 `python` / `go` / `maven` 目前没有下拉入口，用 `envs config set mirror.go aliyun` 这类命令改，或直接在 `settings.json` 里写。
- **GitHub 代理前缀**：给所有走 GitHub 的直链和自更新清单加前缀（例：`https://ghproxy.net/`），不需要末尾斜杠，会自动补。

远程版本索引默认缓存 10 分钟；网络抖动时会退回缓存并明确标注「离线」。点详情页「刷新索引」强制重拉。

## 10. 开机自启与托盘使用习惯

- 自启命令是 `"<安装目录>\EnvSwitch.exe" --tray`，开机静默驻留托盘，不占任务栏窗口
- 常驻托盘的意义是免开主界面切版本：右键 → 目标工具 → 点版本号
- 主界面关闭后仍在托盘；要真正退出请走托盘的「退出 EnvSwitch」，否则新起的实例会因为单实例互斥量直接静默退出（看起来像"打不开"）

## 11. 自动更新与回滚

流程全自动，失败不留半成品：

1. 读清单 `https://raw.githubusercontent.com/HUIdada1/EnvSwitch/updates/latest.json`（企业内网可用环境变量 `ENVS_UPDATE_MANIFEST_URL` 整体替换，或走设置里的 GitHub 代理前缀）
2. 比较版本号 → 下载 `EnvSwitch-win-x64.zip` 到 `update\`，按清单里的 **sha256** 校验
3. 旧 `EnvSwitch.exe` / `envs.exe` 改名 `.old`，新文件就位
4. 新进程带 `--updated` 启动，5 秒内写出 `update\heartbeat` 才算成功；心跳文件由下次启动检查，未写出即判定失败并自动换回 `.old`
5. 成功后保留 `.old` 一段时间，可手动 `envs self rollback` 回退

入口：GUI 的横幅与托盘「检查更新」，命令行 `envs self update`。各版本改了什么见 [releases/](../releases/) 目录，例如 [v1.0.0](../releases/v1.0.0.md)。

## 12. 故障排查

先跑 `envs doctor`（GUI 总览页底部同样内容），它检查 7 项：

| 检查项 | 状态含义 | 处理 |
|--------|----------|------|
| 注册表写入 | `bad` = `HKCU\Environment` 不可写 | 检查组策略 / 防篡改软件；可手动把 §4 的 5 条路径加进用户环境变量 |
| 激活链接 | `bad` = 某工具 junction 失效 | `envs use <tool> <ver>` 重建即可；提示里会列出受影响工具 |
| PATH 优先级 | `warn` = nvm / scoop / `Program Files\nodejs` 排在前面 | `use` 时会自动把 EnvSwitch 条目前移；仍在冲突就卸掉或调整那个管理器 |
| PATH 注册 | `info` = 尚未启用 | 执行一次 `envs use ...` 或 `envs path ensure` |
| nvm / scoop 共存 | `info` | 只读展示，不会删除外部管理器目录 |
| WebView2 | `warn` = 缺运行库 | GUI 起不来但 CLI 正常；装 Microsoft Edge WebView2 Runtime |
| 开机自启 | `ok` / `info` | 显示当前 `Run` 值 |

常见现象：

| 现象 | 原因与处理 |
|------|-----------|
| 装完 java / rust / kubectl 等，命令却提示找不到 | 预期行为：只有 node、python、go 和 npm 系会自动进 PATH。按 §4.1 把 `current\<工具>` 手动加进用户 PATH，新开终端即可 |
| 切了版本，命令行里还是旧版本 | 已打开的终端不会变，**新开终端**。仍不对就 `envs which node` 看 PATH 实际胜出者，多半是外部管理器抢先 → `envs doctor` |
| 下载慢 / 超时 | 换镜像（§9）、配 GitHub 代理前缀；重跑 `install` 会续传 |
| 提示哈希校验失败 | 包被中间设备改写；换源或换代理重试，EnvSwitch 已删除坏包，不会落位 |
| 冒烟自检失败 | 该版本在本机跑不起来（缺 VC 运行库等）。store 里已解包但不会激活，`envs remove` 掉换版本 |
| 想彻底退出 EnvSwitch 对 PATH 的影响 | `envs path restore`（旧值备份在 `path-backup.json`），删除激活链接不影响第三方工具 |
| GUI 双击没反应 | 可能已有实例驻留托盘（看托盘图标）；或首次运行缺 WebView2 Runtime |
| 磁盘紧张 | `envs clean` 清下载与索引缓存；再不够就在详情页卸掉不用的版本 |
| 要报 issue | `envs doctor --bundle`，把 `logs\diag-*.json` 直接附上，里面含版本、home、store、用户 PATH、配置 |

## 13. 已知限制

诚实列出，避免按预期找不到功能：

- **只有 node / python / go 与 npm / npx / pnpm / pnpx / yarn 会自动接进 PATH**；Rust、PHP、Deno、Bun、uv、JDK、Maven、Gradle、.NET、kubectl、Terraform 装完能管能切，但命令行调不到，需按 §4.1 手动补一条
- **`.NET SDK` 不出现在侧栏列表**（分组名 `dotnet` 未在前端四组里），只能从总览卡片进入
- **托盘菜单在 python 上有点击错位风险**（菜单项 id 分配与固定动作冲突）：切 python 版本建议走主界面或 `envs use python <ver>`
- **`JAVA_HOME` 不自动设置**：Maven / Gradle / IDE 需要它时，请指向 JDK 根目录 `%LOCALAPPDATA%\EnvSwitch\store\java\<版本号>`（注意不是 `current\java`，那个链接指向里面的 `bin`），换 JDK 版本时同步改这一处
- **`checkUpdateOnStart` 开关只存不读**：更新入口以横幅、托盘「检查更新」和 `envs self update` 为准
- **`enabledTools` 不参与过滤**：17 个工具全部展示
- **PHP 只列内置的 4 个版本**，没有远程索引；Rust / uv 的镜像选项尚未生效
- **没有运行日志文件**：只有诊断包 `logs\diag-*.json` 与 GUI 启动失败时的 `startup-error.log`
- **不支持 `envs tray` 子命令**（架构文档里提过，代码未实现）
- **前缀匹配不产生歧义错误**：`envs use node 22` 命中多个时取最高版本
- **单实例不做 IPC**：第二个实例静默退出，不会唤起已运行窗口
- 只支持 Windows x64；macOS / Linux 未适配
