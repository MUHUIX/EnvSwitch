## 2. 技术选型（含证据）

### 2.1 决策依据：本机现状实测

| 项 | 实测 | 影响 |
|----|------|------|
| Rust（Tauri 必需） | **未安装** | Tauri 路线需先装 rustup，构建不确定 |
| Go | 1.26.5 windows/amd64 ✅ | Wails 路线**立刻可编译验证** |
| Node | v16.20.2（nvm 管理，另有 22.22.0） | 前端构建锁 Vite 4（Vite 5 需 node 18+）；发布走 CI 不受限 |
| WebView2 Runtime | 已装 ✅ | GUI 渲染底座可用 |
| VS 2022 BuildTools | 已装 | 任何路线的 RC 资源编译都够 |
| 网络（GitHub API / goproxy.cn / npmmirror） | 全部 200 ✅ | 依赖下载与更新源都通 |

### 2.2 候选对比

| 方案 | 体积 | 热更新 | CLI 复用 | 本机可验证 | 结论 |
|------|------|--------|----------|------------|------|
| Electron + Vue | 180 MB+，内存 200 MB+ | electron-updater 成熟 | 需另发 node CLI，双栈维护 | ✅ | ✗ 违反 R11 轻量化 |
| Tauri v2 (Rust) | 5–10 MB | tauri-plugin-updater 成熟 | Rust 双 bin 复用 core | ✗ 无 Rust 工具链 | 备选；引入整条新工具链的成本由用户承担 |
| **Wails v2 (Go) + Vue 3** | 8–15 MB | 自实现（约 200 行，逻辑全控） | **同一 core 包直接编译 CLI/GUI 两个 bin** | ✅ 即刻编译 | **✓ 采用** |
| Neutralino | 极小 | 社区方案弱 | 不适合注册表/重解析点等系统调用 | — | ✗ 能力不足 |

选择 Wails 的第一性理由：**本产品 80% 的难点在 Windows 系统调用（junction、注册表、进程、下载校验），20% 在 UI**。Go 单栈把系统层、CLI、GUI、updater 收敛到同一份 core，测试与演进成本最低；WebView2 是 Win10/11 的标配组件，GUI 侧只输出一份前端。Tauri 的体积优势对本产品量级（十余 MB）不构成决定差。

### 2.3 栈明细

- 后端：Go 1.22+ 语法（本机 1.26 编译），零 CGO，`golang.org/x/sys/windows`、`modernc.org/sqlite`（不用，配置用 JSON 即可）、`spf13/cobra`（CLI）、`github.com/wailsapp/wails/v2`（GUI）
- 前端：Vue 3.4 + Vite 4.5（node 16 兼容）、纯 CSS 变量设计系统（无 UI 框架，保证轻量与「液态玻璃」定制度）、无 vue-router（三视图状态切换）
- 打包：NSIS 3（per-user）+ GitHub Actions（windows-latest）
- 校验：zip/tar.gz 全部 Go 标准库可解（`archive/zip`、`archive/tar`+`compress/gzip`），**无外部解压依赖**

## 4. 核心机制：独立版本库 + junction 切换

### 4.1 磁盘布局（全部 %LOCALAPPDATA%\EnvSwitch，可迁移）

```
EnvSwitch/
├─ settings.json
├─ store/
│  ├─ node/22.22.0/            # zip 解压，根即 node.exe
│  ├─ npm/10.9.4/package/…     # npm registry tarball 解包
│  ├─ pnpm/9.12.3/pnpm.exe     # GitHub 独立二进制 zip（不依赖 node）
│  ├─ yarn/1.22.22/package/…
│  ├─ python/3.12.7/           # python-build-standalone install_only
│  └─ go/1.26.5/go/            # 官方 zip
├─ current/                    # ★ 切换的唯一动作 = 重指这里的 junction
│  ├─ node    → ..\store\node\22.22.0
│  ├─ npm     → ..\store\npm\10.9.4\package
│  ├─ pnpm    → ..\store\pnpm\9.12.3
│  ├─ yarn    → ..\store\yarn\1.22.22\package
│  ├─ python  → ..\store\python\3.12.7
│  └─ go      → ..\store\go\1.26.5\go
├─ bin/
│  ├─ shims/npm.cmd pnpm.cmd yarn.cmd        # 见 4.3
│  └─ envs.exe                               # 安装时复制（CLI shim，可选）
├─ downloads/  logs/  update/  path-backup.json
```

### 4.2 PATH 策略（一次写入，四条目，永不再动）

> M1 实现修订（2026-11-18 真机验证）：js 包工具的包内 .cmd 假设 node_modules 布局，解包形态会断链（npm.cmd 会去找 `bin/node_modules/npm/...`），因此 npm/pnpm/yarn 统一走自生成 shim，PATH 条目从六条收敛为四条。

用户 PATH（HKCU\Environment，REG_EXPAND_SZ）插入且只维护这四条（以 home 前缀 + current\/shims 识别归属）：

```
%LOCALAPPDATA%\EnvSwitch\current\node
%LOCALAPPDATA%\EnvSwitch\current\python
%LOCALAPPDATA%\EnvSwitch\current\go
%LOCALAPPDATA%\EnvSwitch\bin\shims        # npm.cmd pnpm.cmd yarn.cmd npx.cmd…
```

- 插入位置：用户 PATH **最前**。若检测到 nvm-windows 的 symlink 或 scoop shims 也在 PATH，doctor 给出黄色提示与「仍然优先使用 EnvSwitch / 让位」两选（默认前者）。
- 切换 node = 删 `current\node` 重建指向新版本目录（<10 ms）；**PATH 本身零改动**，注册表写入只在首次启用/卸载时发生（ensure 幂等、restore 零残留均已真机验证；改前旧值自动快照 path-backup.json）。
- junction 实现：`CreateFileW(GENERIC_WRITE, FILE_FLAG_OPEN_REPARSE_POINT|FILE_FLAG_BACKUP_SEMANTICS) + DeviceIoControl`。⚠ 实测两个硬坑：① FSCTL 常量以 winioctl.h 为准 —— SET=0x900A4、GET=0x900A8、DELETE=0x900AC（网上大量流传版本写作 A8/A0/A4 是错的，会把 SET 打错门）；② **Go 的 filepath.EvalSymlinks 不解析 junction**，读目标必须走 FSCTL_GET_REPARSE_POINT。免管理员、免符号链接权限；创建失败时 UI 明确报错（不静默复制目录）。

### 4.3 npm/pnpm/yarn 的 shim 模板（已实现，真机验证）

```bat
@ECHO off
SETLOCAL
SET "ES=%~dp0.."
SET "NODE=%ES%\current\node\node.exe"
IF NOT EXIST "%NODE%" SET "NODE=node"
IF EXIST "%ES%\current\npm\bin/npm-cli.js" (
  "%NODE%" "%ES%\current\npm\bin/npm-cli.js" %*
) ELSE (
  ECHO EnvSwitch: npm 未激活版本，请先 envs use npm <ver> 1>&2
  EXIT /B 78
)
ENDLOCAL
```

要点：shim 永远指向 `current\<tool>\<入口js>` 稳定路径，切换 junction 后无需改 shim；优先用 EnvSwitch 激活的 node，无激活时回退系统 node。入口 js 由各适配器以 `Shims() map[命令名]相对入口` 声明（npm→bin/npm-cli.js + npx→bin/npx-cli.js；pnpm→bin/pnpm.cjs + pnpx；yarn→bin/yarn.js），安装与切换时幂等生成。冒烟测试直接跑入口 js（绕开包内 .cmd 的 node_modules 路径假设）。

### 4.4 收编（adopt）已有安装

启动扫描：nvm-windows（settings.txt 的 root，列出 `v*` 目录）、scoop（apps\nodejs*、python、go）、winget 常规安装位、系统 PATH 上现存的 node/python/go。GUI 中作为「检测到」分组展示：
- EnvSwitch 自有 store → 完全可管理（切换/卸载）
- nvm 来源 → 可切换（junction 直指 nvm 版本目录，零拷贝）；卸载按钮禁用并提示去 nvm
- 系统/scoop/winget 来源 → 只读展示 + PATH 优先级说明
不迁移、不删除别人的目录——**对第三方管理器只读，对自己 store 全权**，这是与共存工具的安全边界。

## 5. 工具适配矩阵（安装源与格式 · M1 实测定稿）

**下载校验总策略**：每个 RemoteVersion 携带 `Alts` 备用源；主源网络错误（404/超时/504）自动逐源重试，校验错误（哈希不符）不换源直接失败删件。npm 系包校验语义 = tarball sha512 必须与 registry `dist.integrity` 一致。

| 工具 | 版本索引（默认 / 备） | 包格式 | 校验 | 实测状态 |
|------|----------------------|--------|------|----------|
| node | npmmirror `/-/binary/node/index.json` / nodejs.org `dist`（互为 Alts） | `node-vX.Y.Z-win-x64.zip`（文件名带 v） | 同目录 SHASUMS256.txt | ✅ 20.19.2 经「mirror 404→官方回退+哈希校验+冒烟」全链通过；npmmirror 索引确有滞后（list 有而 binary 无），Alts 即为此设计 |
| npm | registry packument（缩写 Accept 头，体积 1/20） | `.tgz` → 解 package/ 展平 | dist.integrity sha512 | ✅ 10.9.4 冒烟通过（入口 bin/npm-cli.js） |
| pnpm | 同上（registry 包形态；standalone exe 列 v1.1） | `.tgz` | integrity | ✅ 9.12.3 装-切-卸通过（入口 bin/pnpm.cjs） |
| yarn | registry `yarn`（1.x；berry→corepack 列 v1.1） | `.tgz` | integrity | ✅ 1.22.22 通过（入口 bin/yarn.js） |
| python | **auto：GitHub API 6s 快探 → NJU 镜像目录页解析**（互为 Alts）；华为云官方 installer 模式列 v1.1 | `cpython-X.Y.Z+<date>-x86_64-pc-windows-msvc-install_only.tar.gz` | API `digest` 字段 / 镜像资产伴生 `.sha256` | ✅ 3.13.18 经 NJU 40MB 下载+校验+`import pip,venv,ssl,sqlite3` 冒烟通过；NJU 镜像只保留近 ~20 tag（窗口取 16，覆盖 3.12–3.15 共存区间） |
| go | golang.google.cn `?mode=json&include=all` / go.dev 同接口（互为 Alts） | `goX.Y.Z.windows-amd64.zip` | JSON 内 sha256 | ✅ 索引解析验证通过（官方直给哈希） |
| nvm | 不代管安装 | — | — | ✅ 只读收编：settings.txt root 解析（E:\nvm 实测发现），版本列入可切换（junction 直指），卸载引导去 nvm |

- 远程列表缓存 10 分钟 TTL；网络失败回退缓存 + 「离线」标注，本机管理功能不受阻。
- GitHub 代理前缀（settings.proxy）作用于所有 github.com / objects.githubusercontent.com 下载 URL。

## 6. 安装/卸载流水线（一次操作的完整时序）

```
install(tool, ver):
  1 解析目标源 URL（镜像优先级 + 代理前缀）
  2 downloads/ 断点续传下载 .part → 完成改名为 .dl（事件: progress {speed, pct}）
  3 sha256 校验（事件: verify）
  4 解包到 store/<tool>/<ver>.tmp/ → rename 原子落位（事件: unpack）
  5 冒烟：node 跑 `node -v`、python 跑 `-c import sys`、go 跑 `go version`、
    pnpm.exe 跑 `-v`，输出与目标版本一致才标记 installed（事件: smoke）
  6 清理 .dl/.part；registry 更新
  失败路径：任一步出错 → 删临时 → 事件 error{stage} → 状态回滚（可重试）

uninstall(tool, ver):
  安全闸：当前激活版本 → 先要求切走（GUI 引导一步完成；CLI --force 拒绝，需 --cascade）
  store 目录删除 + registry 更新（保留 downloads 缓存供重装，`clean` 手动清）
```

## 7. 热更新协议（exe 版本，零服务器）

更新清单 `updates` 分支的 `latest.json`（CI 发布时生成；raw.githubusercontent 读取，代理前缀可配）：

```json
{
  "version": "1.0.0",
  "date": "2026-11-18T12:00:00Z",
  "notes_zh": "…release body…",
  "platforms": {
    "windows/amd64": {
      "url": "https://github.com/HUIdada1/EnvSwitch/releases/download/v1.0.0/EnvSwitch-win-x64.zip",
      "sha256": "…",
      "size": 12582912
    }
  }
}
```

- 比较：构建期 `-ldflags "-X main.version=v1.0.0"`，semver 比较；GUI 启动后延迟 30 s 静默检查一次（设置可关），CLI `envs self update` 手动。
- 应用（GUI 进程内自替换）：下载 zip → 校验 → `MoveFileEx(EnvSwitch.exe → EnvSwitch.exe.old)`（Windows 允许重命名运行中 exe）→ 新文件放入 → spawn 新进程（带 `--updated` 参数）→ 当前进程退出 → 新进程启动即删 `.old`（失败则下次启动删）。
- 回滚：`.old` 保留期内 `envs self rollback` 双向 rename；启动自检（新版本 5 s 内未写 heartbeat 文件）自动回滚并禁用下次自动检查（提示手动）。
- 安全边界：仅 HTTPS + sha256；清单可改指向自有域名。代码签名列为 roadmap，不阻塞 v1（源码公开可审计 + CI 构建日志公开）。
- 前端资源（HTML/JS/CSS）编译期内嵌 exe，随热更新一起替换，**不做资源级独立热更**（少一层状态，简单即正确）。

## 8. CLI 命令集（`envs`）

```
envs status                        各工具当前激活版本 + 来源 + PATH 胜出者
envs list node                     已安装列表； --remote 远程可装； --filter 18
envs use node 22.22.0 | 22 | latest    切换（前缀模糊 → 唯一匹配，多义报错列举）
envs install pnpm@9.12.3 / 分开两参  安装（-y 跳冒烟？默认必跑）
envs remove go 1.22.5              卸载（当前激活需 --cascade 先切走）
envs which node                    解析当前实际生效的 node.exe 全路径
envs doctor                        体检：PATH 顺序/junction 健康/写权限/冲突管理器/WebView2
envs autostart on|off|status
envs tray                          弹出托盘快速切换浮层（等效 GUI 迷你面板）
envs config show|set mirror.node <url> | set proxy <url> | set store <path>
envs self update | self rollback | envs version
envs gui                           打开主窗口（等同双击 exe）
```

输出全部支持 `--json`（脚本集成）；退出码：0 成功 / 2 参数错 / 3 网络 / 4 校验失败 / 5 权限 / 6 版本歧义。

## 9. 桌面应用（EnvSwitch.exe）

- 窗口 1240×800（最小 1024×680），frameless？——**否**，保留原生标题栏（拖拽/贴边/高 DPI 行为全免费），自绘仅覆盖内容区，符合「轻量可靠」。
- 关闭按钮 → 最小化到托盘（设置可改为退出）；托盘左键=显示窗口；托盘右键菜单=六工具子菜单列出版本，点击即切（免开主界面，对应 R5）。
- 单实例：命名互斥量 `Local\EnvSwitch.SingleInstance`；二次启动发 IPC 唤醒主窗。
- 开机自启：HKCU Run `EnvSwitch = "<exe>" --tray`；GUI 设置开关即时写入/移除；安装包完成页默认勾选。
- 通知：安装完成/失败、发现新版本，走 wails 系统通知（Win10/11 原生 toast）。

## 11. 兼容与安全清单

- 目标：Windows 10 1809+ / Windows 11，x64；arm64 交叉编译预留（Go GOARCH=arm64，node 索引有 win-arm64）。
- 全程不需要管理员；不写 HKLM；不动别人的 PATH 项与安装目录。
- 卸载器删除自身 store（二次确认 + 「保留已下载版本包」选项）并移除其四条 PATH。
- Defender：自替换行为是更新器常见模式，白话写在 README 安全 FAQ；CI 产物附 sha256 清单。

## 16. 自我反驳（已审视的反对意见）

1. **「Tauri 更小更主流」——** 体积差对本量级（~12 vs ~8 MB）无感；换 Rust 引入工具链成本，且系统调用（junction/注册表）Go 生态同样成熟。维持 Go。
2. **「junction 会不会被杀毒软件盯上」——** 重解析点为 nvm/choco/volta 同类工具普遍使用，行为白名单内；README 公开机制说明即可。
3. **「为什么不直接调 nvm 命令切换」——** 那是命令行的重复劳动，违背 R5；且 nvm 每次切换动注册表 PATH、需要管理员/开发者模式建 symlink，痛点正是我们解决的。
4. **「热更新自替换危险」——** 已用 .old 双缓冲 + heartbeat 自检 + CLI 回滚三重兜底；不更新只影响新功能，不砖基础环境（store 与 PATH 独立于主程序）。
5. **「一个 exe 同时当 CLI 和 GUI 更轻」——** 曾考虑；拆两 bin 使 CLI 产物无 GUI 依赖、可进 PATH/Scoop 分发，且体积更小（GUI 资源不拖累 CLI），利大于弊。
