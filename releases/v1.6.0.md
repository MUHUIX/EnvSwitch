# EnvSwitch v1.6.0

这版把「看环境」这件事理顺了：常用的排在前面，异常的直接帮你修好，修错了还能一键退回去。

## 排序规则统一

- 环境总览卡片与左侧栏的每个分组，一律按「已安装使用的在前、未安装的在后」排序，两组内部各按 A-Z。
- 修掉一个明显别扭的现象：Git、Docker、kubectl 这类由安装器装到系统里的工具，界面上明明显示着生效版本，却因为版本库里没有它而被排到未安装区——现在「本机有可用版本」和「系统里检测到并在用」都算已安装使用。
- 同一套排序口径只有一个来源（`frontend/src/sort.js`），总览、侧栏、轮询刷新不会再各排各的。

## 新增：环境诊断一键修复 + 一键撤销

以前 `envs doctor` 与总览底部的诊断面板只能报问题、给手动修法；现在能自动处理的项直接点「修复」。

- **可以修的**：
  - `PATH 优先级`——被**用户 PATH** 里的别家目录抢先时，把 EnvSwitch 自有条目整体提到最前，并按新表复检一次；
  - `空壳 PATH 条目` / `PATH 条目来源`——摘掉体检点名的 EnvSwitch 自有条目（空目录壳、孤儿记录、指向临时目录 / 构建产物 / git 工作区的路径）；
  - `激活链接`——`current\<tool>` 指向的目录被外部删掉后，重指到本机已装的最新版本（等价于 doctor 提示的「重新 use 即可修复」）；
  - `托管变量层级`——`JAVA_HOME` / `GOROOT` 漂走或多了一级 `\bin` 时，校准回当前激活版本根。
- **修完当场复检**：结论逐条列在诊断卡片下方，通过才打 ✓；没修好会写清楚「仍有」「跳过」，不把没解决的事报成成功。
- **支持回退**：任何一次改用户 PATH 之前，先把原值快照到 `%LOCALAPPDATA%\EnvSwitch\doctor-fix.json`，快照落盘失败就一个字节都不动注册表。GUI 诊断卡片右上「撤销上次修复」，CLI 是 `envs doctor --undo`。只能撤销最近一次（撤销 = 回到上一次修复之前）。
- **不支持自动修的一律不给按钮**，改标「需手动」并说明原因：系统 PATH 抢位要管理员（EnvSwitch 不动系统段）、注册表被组策略锁死、WebView2 缺失要装运行库。这类判断宁可保守，也不做半吊子写入。
- CLI 同口径：`envs doctor --fix` 修所有可修项，输出末尾把仍异常的项标出「可修复 / 需手动」。
- 边界：只增删、重排 **EnvSwitch 自己写进用户 PATH** 的条目；仍在服役的路径（有效激活链接、有内容的 shims / 安装目录）即使被点名也拒绝摘除——摘了会比原来的警告更糟。不碰系统 PATH，不删任何目录内容。

## 问题修复

- **激活链接失效后切不了版本**：目标目录被外部删除时，`Switch` 的旧判据（`junctionTarget` 是否有效 + `os.Stat` 链接是否存在）在死链上双双落空，跳过摘链接，紧接着创建就报「文件已存在」——即「重新 use 即可修复」这句话本身在你机器上做不到。改为按 `Lstat` 判断链接自身存在、死 junction 走 `FSCTL_DELETE_REPARSE_POINT` 摘除，卸载最后一个版本时的摘链接同样受益。
- 「需手动」的诊断项不再挤掉说明文字：详情过长中段省略并保留完整悬浮提示。

## 界面

- 详情页「安装位置」卡片支持收起：标题行右侧箭头一键折叠，只留版本库根目录一行；偏好按应用记住。

## 升级

v1.4.0 及以后的版本可在设置页热更新；更早的版本请下载 `EnvSwitch-Setup-v1.6.0.exe` 覆盖安装。
