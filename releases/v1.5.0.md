# EnvSwitch v1.5.0

这版把「切版本」从全局下沉到项目目录：给某个目录绑好版本，进去就自动对版、离开自动还原。功能默认关闭，要不要用、用到哪一层，由你自己选。

## 新增：目录级版本绑定

- `envs bind <tool> <版本> --cwd <目录>` 给项目固定版本，支持 node / npm / npx / pnpm / yarn / python / go 及各自的宿主命令；`envs unbind` 解绑，`envs bindings` 看表，`envs bind why` 说清当前目录的版本是怎么定下来的。
- `envs bind enable` 打开总开关（默认关）；`envs use <tool> <版本> --here` 只绑当前目录、不动全局激活链接。
- 主路径是会话钩子：`envs init powershell|bash` 装进你的 profile（不加 `--append` 只预览）；进目录自动前置对应版本目录，离开按快照还原，不会在 PATH 上越叠越长。同目录回车零进程创建。
- 不想装钩子就用 `envs run -- <命令>` 或 `envs shell`，一次前缀、任意终端可靠。cmd.exe 只在**新开窗口**生效（没有 cd 事件），已开的窗口不会变。
- 绑定表单独放在 `%LOCALAPPDATA%\EnvSwitch\bindings.json`，不混进 `settings.json`，也不受 GUI 常驻内存配置回写的影响；写盘走 `.tmp` + 重命名与锁文件，损坏时自动改名隔离并整体回退全局版本，不弹错误框。
- 绑定版本没装时**不会自动下载**：本次先用全局版本并提示补装命令。网络盘 / UNC 路径不允许绑定。
- 上游自己管版本的（`global.json`、`go.mod` + `GOTOOLCHAIN`、corepack、venv / uv、gradlew / mvnw）自动让位、不注入；绑定 go 时带上 `GOTOOLCHAIN=local`，免得 go 又自己去下工具链。`node_modules` 里的 `.nvmrc` 不作数，`engines.node` 只提示不生效。
- 逃生门齐全：`ENVS_DISABLE=1` 让整棵进程树立刻回到全局；`envs init --remove` 按 BEGIN/END 标记精确删除自己写的那一段，profile 原有内容一个字不动；`envs bind disable --rewrite` 关掉总开关并同步重生成钩子读的表。

### 边界（实测，不是推测）

- WSL、容器、devcontainer、JetBrains 的 Run Configuration、按绝对路径起进程的 GUI 工具，结构上做不到自动对版——请从绑定目录启动 IDE，或复制解释器的绝对路径。
- `npm run` 会把 `<项目>\node_modules\.bin` 顶到 PATH 首位，scripts 里直接写的 `node` 不经过 EnvSwitch 的 shim；层 2 兜底只认绑定表前 12 行、目录上溯 8 级，其余场景靠会话钩子或 `envs run`。
- 这台机器如果本来就有系统级 node / npm，层 2 shim 可能被抢位；用它之前先看 `envs doctor` 给出的 PATH 优先级结论。
- `pip`、`nvm-windows`、`docker` 不支持绑定；`java` / `maven` / `gradle` 尚未纳入本期绑定范围。

## 体检与诊断

- `envs doctor` 的 PATH 判定改为「系统 PATH + 用户 PATH」全表真实解析：以前用户段里有自己的条目就报绿灯，哪怕本机 `node` 其实被 `C:\nvm4w` 抢走；现在直接点名是谁抢的、来自系统段还是用户段，并给出手动修法。
- 新增空壳 PATH 条目、条目指向临时目录 / 构建产物 / git 工作区、层 2 表规模、托管变量层级、绑定表自身健康度等检查项。
- `envs which <tool> --cwd <目录>` 并排显示「PATH 实际胜出」与「绑定应得」，不一致时标出来，不用猜为什么没生效。
- `--json` 契约收紧：stdout 只输出合法 JSON，诊断信息一律走 stderr；失败也返回结构化错误与退出码。

## 稳定性修复

- 单实例锁提到更新流程之前：旧实现可能让抢锁失败、已经退出的进程先写下 heartbeat，十分钟内误判更新成功，过期后又把新版本回滚——两个方向都判反。现在只有拿到锁才写凭据。
- 热更新 / 回滚拉起的新进程走等锁启动，不会在上一进程尚未退场时被自己的锁弹死；等锁超时写 `relaunch-error.log` 留现场，不再只是「双击没反应」。
- 更新成功后顺手清掉更早的崩溃残骸 `.broken`。
- `OwnedPathEntries` 把 shims 顺序提到三个 runtime 激活链接之前：node 版本目录自带 `npm.cmd`，旧顺序下自己生成的 npm shim 一次都不会被搜到。顺序调整保持幂等。
